## Findings: where systems interact badly

### P0: breaks the testnet demo

1. **A round that misses K_MIN can never close. It permanently blocks the service and locks every committer's stake.** `finalize` reverts `TooFewReveals`; `openRound` for that service then reverts `RoundAlreadyOpen`; each committer's `activeRound` stays set, so they can neither withdraw nor commit anywhere else. A throwaway Hardhat test confirmed this on the current contracts (run, then deleted).
   - Testnet makes it likely. K_MIN is 3 and there are exactly 3 critic accounts. A critic can be in only one round at a time. `scripts/demo/list-services.ts` lists all 5 services back to back, which opens 5 rounds with 90 s commit windows at once.
   - Result: at most one service can get 3 commits. The other four stay in probation forever. One failed reveal also locks all three critics.
   - Fix: ticket 25's void finalisation (void, release all committers, slash non-revealers). It must land before the testnet redeploy.
2. **Only the API and the ENS listing relayer run as standalone processes.** Missing:
   - a critic daemon that watches `RoundOpened`, reviews the service, then commits and reveals (`apps/critic` has no `start` script);
   - a keeper that calls `finalize` after the reveal window and opens re-review rounds. Nothing opens round 2 or later; only listing opens round 1;
   - a service runner: `apps/services/*` have no `start` scripts.

   The ENS score relayer (`relayer scores`) runs once and exits. Every e2e test drives these steps by hand, so "unattended" exists only inside tests. Ticket 27 needs all of these.
3. **The popularity signal is never fed.** The services' x402 `onSettled` only logs and never `POST /calls`. On a real run every `popularityCalls` is 0, so the popularity buyer picks the lowest id instead of the gamer. Separately, the buyer CLI is still local-x402-only (`apps/buyer/src/cli.ts`), although Hedera mode exists in `@skeptique/x402-client`.

### P1: robustness

4. **The score relayer aborts the whole pass on the first unmapped name.** A finalised service or registered critic that is missing from the JSON mapping throws in `apps/relayer/src/score-source.ts`, and so does a namehash mismatch. One web-listed service or one newly onboarded critic stops ENS updates for everyone. It should skip that item, report it, and carry on.
5. **Two sources of truth for ENS names.** The listing relayer derives the slug from `suite.serviceName`; the score relayer and the API need a hand-written `serviceNames` map. Also, two sellers using the same `serviceName` get the same slug: the second one is silently skipped (the subname already exists) and both rounds publish to one name.
6. **`GET /events` load.**
   - Each SSE subscriber runs its own 500 ms RPC poll starting from the deployment block, with no heartbeat (proxies drop idle streams, and a reconnect replays everything).
   - In `apps/web/components/latest-round.tsx`, every replayed event fires a `getRound` fetch, and each fetch makes the API rescan logs.
   - Responses can arrive out of order and show an older phase.
   - With Hedera's rate-limited public RPC, a few open tabs slow down the whole API.
   - Fix: one shared poller fanning out to subscribers, keep-alive comments, debounce the refresh on the client, drop stale responses.
7. **State held only in memory:** evidence store, popularity counter, buyer runs, World nonces. Restarting the API empties the review evidence on service pages. `DATABASE_PATH` is already in `.env.example` but unused.
8. Every API read rescans logs from `deploymentBlock`. That is fine inside Hedera's 7-day log window for the hackathon; caching would cut RPC load.

### P2: hygiene

9. Packages that boot chains time out under `pnpm -r test` parallelism. Raise `testTimeout` in those packages, or document `--workspace-concurrency=1`.
10. The untracked nested clone `skeptique/` (old commit 7ddcbc7) contains `.env` and `.env.bak-01`. It breaks local lint and could get swept in by `git add -A`. This checkout has no `.env` of its own.
11. Leftover worktrees in `.claude/worktrees/` (card 11, 13, 14, 15, 16) are fully merged.
12. Gaps against spec/02:
    - `NOREVEAL_SLASH_BPS` is never applied (ticket 25).
    - Slashed funds have no way out (ticket 22).
    - The bounty is never debited, so `BountyExhausted` cannot fire.
13. Suite `judge` cases have no production judge adapter; only tests' fixed judge exists. `LLM_PROVIDER` is ignored: the code supports OpenAI-compatible APIs only.
