# 09: Seller lists from the web form (receipt)

## What changed
- `apps/web/lib/sell.ts`: `listService({ provider, registry, form })` runs from the seller's EIP-1193 wallet.
  - It reads `minListingFee` from the chain and rejects a lower fee (`ListingError` kind `invalid`) before any transaction.
  - It fetches the public suite, validates it against `TestSuiteSchema`, and checks name and category match it. A bad URL, a non-suite body or a mismatch is kind `suite`, also before any transaction.
  - It sends `listService` with the fee as value, waits for the receipt, and returns `serviceId` and `specHash` from the `ServiceListed` log.
  - A wallet rejection (EIP-1193 code 4001) is kind `rejected`: "Transaction rejected in your wallet, so no listing was created."
  - `previewSuite` gives the hash to show before paying. `parseHbar` and `suiteUrlFor` are helpers.
- `apps/web/components/sell-form.tsx` and `app/sell/page.tsx`: the form. "Show suite hash" previews the hash, and "List service" is enabled only after a hash is shown. Success goes to `/services/<id>`.
- `apps/web/components/service-detail.tsx`, `app/services/[id]/page.tsx`, `fetchService` in `lib/api.ts`: the service page shows bounty, price, status and the ENS name from the API. An empty `ensName` is shown as "Pending: created after listing". Nothing is hard-coded.
- `apps/services/common/server.ts`: `access-control-allow-origin: *` on responses, so the browser can read a service's public suite.
- `.env.example`: `NEXT_PUBLIC_SERVICE_REGISTRY`. `apps/web` gains the `viem` dependency.
- `e2e/seller-lists-web-form.e2e.test.ts` (`describe("seller lists from the web form")`, 4 tests): fee below minimum, bad suite URL, rejected wallet (no listing, `/services` empty), and a successful listing whose page shows the bounty and Pending. Written failing first (commit 898b483).

## Spec deviations / notes
- The e2e drives `listService` with a local EIP-1193 wallet and renders `ServiceDetailView` with `renderToString`. It does not run a browser, so the form component is only covered by the existing page render test.
- The suite URL must be `<endpoint>/../suite.json`, because that is where the API indexer reads it; any other URL is refused.
- Fee and price are entered in HBAR. The fee is sent as the transaction value in tinybars, correct for the local chain; ticket 21 must scale to weibars on Hedera (see board/done/08.md).
- ENS node is sent as zero. Ticket 12 creates the name.
- The sell page navigates with `window.location.assign` rather than `useRouter`, so the existing page render test still works.
- `tsc --noEmit` on all of `apps/web` hung for me, so I checked only the changed files with a temporary tsconfig (removed).
