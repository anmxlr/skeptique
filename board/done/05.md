# 05: Spike: World ID Agent Pass (receipt)

## What changed
### Note: `spec/notes/world.md`
Covers every item the ticket lists, each sourced to auth.world.org, docs.world.org, or World's official repos (`worldcoin/idkit`, `worldcoin/simulator`) and npm packages:
- **Request/response flow:**
  1. The server signs an `rp_context` with `signRequest` from `@worldcoin/idkit-server@1.2.0`.
  2. The client calls `IDKit.request(...).preset(proofOfHuman({ signal }))` from `@worldcoin/idkit-core@4.6.0`.
  3. The user approves in World App (or the simulator does).
  4. `pollUntilCompletion` returns the 4.0 result, and the client forwards it to our backend.
- **Server-side validation:** `POST https://developer.world.org/api/v4/verify/{rp_id}` with the result passed through unchanged and `environment` set by the server. The note gives the 200 and 400 shapes.
- **Secrets:** only `signing_key` is server-side. `app_id` and `rp_id` are public. The verify API takes no secret.
- **Per-human id decision:** use the returned `responses[0].nullifier` (scoped to user + RP + action, action `register-critic`), stored as bytes32 `0x`+64 hex via BigInt. World does not dedupe nullifiers, so the API and the contract must.
- **Failure recipes** for denied, expired and cancelled, written for ticket 16.

### Spike: `spikes/world/`
Plain node with its own `package.json`, outside the pnpm workspace. It reads `WORLD_APP_ID`, `WORLD_RP_ID` and `WORLD_SIGNING_KEY` from the root `.env`.
- `server.mjs`: a local backend.
  - `POST /world/rp-context` signs the request.
  - `POST /world/verify` checks environment and action, calls World's verify API, normalises the nullifier, enforces one-per-human, and returns 200 `{nullifier, expires_at_min}` or 403 `{reason}`.
- `spike.mjs`: drives a real staging proof headlessly. It gets the proof from the official World simulator MCP tool `complete_test_request` and posts it to the server three times: valid, tampered and replayed.
- `spike-transcript.txt`: saved run output. It contains no secrets and no connector URLs.

## Spec deviations
- **"Agent Pass" naming:** no World page uses that name. auth.world.org documents World IdP (OIDC), but our portal credentials are World ID 4.0 RP credentials, which belong to IDKit and the v4 verify API. We integrate IDKit 4.0, the only path our credentials support. The submission should explain this mapping.
- **Mocked proofs:** we read "mocked" on the event page as staging proofs from the official simulator. The spike validates those with `environment: "staging"`. A production deploy would force `environment: "production"`, because staging accepts test identities.
- **spec/03 `/world/verify` (proposed, not applied):** the note lists three changes.
  1. The body is the IDKit 4.0 result plus the critic address used as the signal.
  2. Add `POST /world/rp-context`, since the client needs a server-signed `rp_context`.
  3. `expiry` should mean the attestor voucher expiry, because World returns no proof expiry on success; the closest field is `expires_at_min`.
- **Failure paths not exercised:** expired and cancelled are documented recipes only. The simulator only completes requests, and the done-when asks for one denial. Ticket 16 owns them.
