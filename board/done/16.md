# 16: World Agent Pass critic onboarding, with denied paths (receipt)

## What changed
### API: `apps/api/src/world.ts`, wired as `AppDeps.world`
- `POST /world/rp-context` signs an IDKit request with `WORLD_SIGNING_KEY` via `signRequest` from `@worldcoin/idkit-server`, and remembers the nonce with a deadline on the server's own clock.
  - Returns `{ app_id, action, environment, rp_id, nonce, created_at, expires_at, signature }`. The browser gets the public World settings from here, so the web app needs no World env vars.
- `POST /world/verify` (IDKit 4.0 result + `critic`) checks, in order. Every denial is a 403 `{ reason, detail? }` and signs no voucher.

  | Check | Denial reason |
  |---|---|
  | An IDKit error was forwarded | `cancelled` (`user_rejected`, `verification_rejected`, `cancelled`), `expired` (`timeout`, `rp_signature_expired`, `timestamp_too_old`, `request_expired`) or `unverified` |
  | Result shape and critic address | `unverified` |
  | Nonce issued here and not yet used (single use) | `unverified` |
  | Request not past its deadline | `expired` |
  | `environment` and `action` | `wrong_environment` / `wrong_action` |
  | `signal_hash` = `hashSignal(critic)`, so a proof can't be replayed for another wallet | `wrong_signal` |
  | World's verify API | `invalid_proof` (World's code in `detail`) |
  | Nullifier not already vouched, and not on chain (via the CriticRegistry index from ticket 10) | `duplicate_human` |

  Only after every check passes does it return `{ nullifier (bytes32), expiry, sig }`: the attestor's EIP-191 signature over `keccak256(abi.encode(nullifier, critic, expiry, chainid))`, exactly what CriticRegistry verifies.
- `createWorldVerifier` POSTs to `https://developer.world.org/api/v4/verify/{rp_id}` with the server's `environment` and a 10 s timeout.
- The World routes answer CORS preflights and allow any origin. They take no cookies; every check is on the payload.
- `src/index.ts` enables World when `WORLD_APP_ID`, `WORLD_RP_ID`, `WORLD_SIGNING_KEY`, `ATTESTOR_PRIVATE_KEY` and `WORLD_ENVIRONMENT` are all set. `WORLD_ENVIRONMENT` is new in `.env.example`, default `staging`, which accepts simulator proofs.

### Critic: `apps/critic/src/onboard.ts`
`registerWithWorld({ apiUrl, result, critic, rpcUrl, registry })` posts the result to `/world/verify`. It stakes `minStake` and calls `registerCritic` **only** when a voucher comes back; any denial returns `{ status: "denied", reason }` without sending a transaction.

### Web: Critics page
`components/world-verify.tsx` runs the flow:
1. The person enters the critic wallet and clicks "Verify with World ID".
2. The page fetches `rp-context` and starts `IDKit.request(...).preset(proofOfHuman({ signal: critic }))`. IDKit is loaded with a dynamic import.
3. It shows the "Open in World App" link, plus a World ID simulator link on staging, and a Cancel button.
4. It sends the result to `/world/verify`, including IDKit failures, so the reason shown is always the server's.

Each denial has its own message ending "Your critic was not registered." Success shows the voucher. `lib/api.ts` gained `post`.

## Deviations / notes for the team
- **Mocked proofs.** The e2e replaces World's verify API with a local stand-in that accepts the staging fixture proof and rejects an altered one; CI can't reach the World simulator. The real simulator → `developer.world.org` path is proven in spike 05's transcript.
- **spec/03, additive:** `/world/rp-context` also returns `app_id`, `action` and `environment`. `/world/verify` denial reasons are the fixed set above.
- **Registration from the page:** the page ends with the voucher, and the critic agent stakes and registers. `registerWithWorld` does the whole verify-and-register path for an agent. A CLI that registers from a pasted voucher on testnet is left for ticket 21/27, once the Hedera deployment addresses exist.
- **Not fixed here (ticket 10's route):** `GET /critics` sends no CORS header, so the critics list fails in the browser when the web app and API are on different origins. Only the World routes, and ticket 24's `/buyer/runs`, allow cross-origin reads.
- **Voucher deduplication** within one API process is in memory. Across restarts the on-chain check, plus CriticRegistry's `DuplicateNullifier`, still blocks a second critic.

## World friction notes (raw, for ticket 32's debrief)
- IDKit rejects a malformed RP id on the client with "Invalid configuration: Invalid RP ID: must start with 'rp_'". It's a helpful message, but the format isn't stated on the integrate page.
- `signRequest` always stamps wall-clock time and has no clock parameter, so servers that test expiry must track their own deadline per nonce.
- `pollUntilCompletion` never throws, but its error codes overlap: `cancelled` vs `user_rejected` vs legacy `verification_rejected`. We map all three to "cancelled".
- No documented way to make the simulator produce a cancelled or expired result; only success is simulatable.
