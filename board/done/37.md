# 37: Demo services standalone, paid-call reports, buyer on Hedera

## What changed
- `apps/services/common/report.ts`: `reportPaidCalls` posts `POST /calls { serviceId, payer }` to `API_URL`; failures are logged, never thrown.
- `common/paywall.ts`: `onSettled(txId, payer)` now passes the settlement's payer. `paywallFromEnv` reports when `API_URL` and `SERVICE_ID` are set.
- `apps/services/start.ts` + a `start` script in each of the five services (`tsx ../start.ts <name>`); `HOST` defaults to `0.0.0.0`, `PORT` from env, `PRICE_PER_CALL` defaults to `1`. Adds `tsx` devDependency (lockfile updated).
- `apps/buyer/src/mode.ts`: Hedera mode when `X402_FACILITATOR_URL`, `BUYER_ACCOUNT_ID`, `BUYER_PRIVATE_KEY` are all set, else local; `cli.ts` uses it.

## Tests
- `pnpm --filter @skeptique/services test -t "reports paid calls"`: 2 passed.
- `pnpm --filter @skeptique/buyer test -t "hedera mode"`: 2 passed.
- Full `vitest run` in apps/services (13) and apps/buyer (10) pass; `tsc --noEmit` clean for both.

## Deviation / risk
- API `POST /calls` requires a `0x` EVM address payer, but the x402 settlement payer is likely a Hedera account id (`0.0.x`) and is unverified. If so the API returns 400, the service logs it, and `popularityCalls` stays 0. Needs a payer-to-address mapping or a relaxed API schema; out of scope for this ticket.
- If the settlement names no payer, no report is sent (logged).
