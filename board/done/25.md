# 25: Void round when too few critics reveal

## What changed
- `RoundManager.finalize`: if `nReveals < kMin` the round is voided instead of reverting `TooFewReveals` (error removed). Void marks the round finalized, emits `RoundFinalized(isVoid=true, median=0)`, slashes `NOREVEAL_SLASH_BPS` (1000) of each non-revealer's stake, releases every committer's stake and clears the service's open-round marker. The bounty is untouched (it stays in the service pool). A repeat `finalize` reverts `AlreadyFinalized`, changing nothing.
- `NOREVEAL_SLASH_BPS` added to the shared ABI.
- Tests: `contracts/test/VoidRound.test.ts` (5 cases), `e2e/void-round.e2e.test.ts`.
- Marketplace/service page already treat `isVoid` events as void (ranking keeps previous score); no change needed.

## Output tail
- `npx hardhat test --grep void` (in `contracts/`): 5 passing; full contracts suite 32 passing.
- `pnpm e2e -t "void round"`: 1 passed.

## Deviations
- `NOREVEAL_SLASH_BPS` is a contract constant, not a constructor arg, to avoid changing every deploy call. Ticket 22 can promote it if needed.
- Non-revealers are slashed only on void rounds; valid-round non-reveal slashing is left to ticket 22.
- `pnpm --filter contracts test --grep "void"` is rejected by pnpm ("Unknown option: 'grep'"); I ran hardhat directly. The local stack uses K_MIN=1, so the e2e void case is a round with zero reveals.
