# 11: Critic tests a service and publishes evidence

## What changed
- The critic runner (`apps/critic/src/runner.ts`: hash check before any call, weighted `suitePass`, p50/p95, error rate, `criticCall` tag), `createLocalPayAndCall` (`onBeforePay`, max-price guard, local mode with no tx id) and `POST /evidence` / `GET /evidence/:hash` already existed on main with unit tests, so this ticket did not rewrite them.
- `apps/api/src/app.ts`: `buildApp` now registers the evidence routes (default in-memory store, injectable via `deps.evidence`). Before, the routes existed but were never mounted.
- `apps/web`: `ServiceDetailView` takes optional `evidence` and renders an Evidence section (critic, score, cases passed, p50/p95). `fetchEvidence` in `lib/api.ts`; the live page loads it when the URL carries `?evidence=<hash>`.
- `e2e/critic-publishes-evidence.e2e.test.ts`: seed lists unit-convert, critic fetches `/services/1/suite`, checks the hash, runs through local `payAndCall`, publishes, evidence is fetched back by hash, bad evidence (score 101) gets 400, unknown hash 404, service page renders the evidence.

## Spec deviations
- spec/03 has no route linking evidence to a service (evidence only carries `roundId`), so the page finds it by `?evidence=<hash>` rather than by service id. A later ticket that indexes rounds can replace this.
- unit-convert's suite contains `judge` cases, so the e2e passes a fixed judge (`async () => true`, model `fixed-judge`); no LLM is called. The score is therefore 100 by construction there.
- Evidence store is in-memory; persistence (SQLite) is not part of this ticket.
