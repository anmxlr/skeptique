# 30: Web polish (receipt)

## What changed
### Live updates
- **API `GET /events`** (`apps/api/src/events.ts`): server-sent RoundManager events (`RoundOpened`, `CriticCommitted`, `CriticRevealed`, `RoundFinalized`), each validated against `EventSchemas` from `@skeptique/shared`.
  - A new subscriber first gets every earlier event (replay), then new blocks, polled every 500 ms.
  - Open streams are closed when the API shuts down.
  - The harness wires it whenever RoundManager is deployed (`AppDeps.events`).
- **Service page** (`components/latest-round.tsx`): a "Latest round" section listens to `/events`.
  - On any event for this service's newest round it re-reads `GET /rounds/:id`, so the phase shown is the API's own, including time-based phase changes.
  - It shows the round number linking to `/rounds/:id`, the phase, and the consensus score once finalized.
  - The section is `aria-live="polite"`.

### Honesty
- **Demo-mode banner** on every page: the team runs the critic agents, so the consensus is staged. Links to the limits page.
- **Limits page** (`/limits`, in the nav): what spec/02 §6 does not defend, led by the staged demo consensus, then what it does defend.

### Finish
- **Loading skeletons** (`components/states.tsx`) on Marketplace, Critics, service and Buyer pages. Screen readers get one status message, and the placeholder cards are hidden from them. The shimmer respects reduced-motion settings.
- **Errors:** styled first-load errors. A toast appears when a refresh fails while the last good data stays on screen.
- **Buyer page:** no longer says "Not run yet" while it is still loading.
- **Keyboard:** "Skip to content" now actually moves focus into the main content (`<main tabIndex={-1}>`). Before, the next Tab still landed in the header.
- **Contrast:** the toast was grey text on near-black, because `.page p` overrode it. Fixed and covered by a test.

## Acceptance criteria
- **Round phase change without a reload:** a Playwright test opens `/services/1`; the stream announces the round opening, then finishing. The page goes from "Commit" to "Finalized · consensus score 88", and a marker set on `window` beforehand survives, so the page never reloaded.
- **Lighthouse accessibility ≥ 90:** I used axe-core (`@axe-core/playwright`), the engine behind Lighthouse's accessibility score, rather than Lighthouse itself. It finds **zero** WCAG 2.1 A/AA violations on Marketplace, service, Critics, Sell, Buyer, Audit and Limits, in light and dark themes, which is stricter than a score threshold.
- **Scripted walkthrough with no console errors:** the same walkthrough fails on any console error or page error, and passes on every page in both themes. It runs against a mocked API at a reserved `.test` host, so no chain is needed.
- **Whole repo:** `pnpm -r build`, `pnpm e2e` (26 passed) pass. `pnpm -r --no-bail test` passes except `scripts/demo/seed.test.ts` (Windows-only `EPERM`; already failing on `main`). `pnpm lint`'s single error is in the git-ignored local `.claude/settings.local.json`; CI does not see it.
