# 14: Walking skeleton 2: one round end to end

## What changed
- `ServiceRegistry.setRoundManager` (deployer, one-shot): `listService` now opens round 1 on the RoundManager.
- `RoundManager.setServiceRegistry` (deployer, one-shot): once set, `openRound` needs a listed service with bounty left (`BountyExhausted` / `InvalidService`). Anyone can still open a new round when none is open.
- `packages/shared/abi/RoundManager.ts`; `RoundView.committed` (addresses in commit order, defaults to `[]`).
- API: `createRoundSource` indexes RoundManager events into `RoundView`s; `GET /rounds/:id` is now backed by the chain; `withRounds` puts the latest finalised median, reveal count, round count and time on `/services`.
- Harness/`deployLocal`: deploys and wires RoundManager with the spec demo windows (90/45 s) and `K_MIN = 1` (`LOCAL_ROUND_CONFIG`).
- Critic: `createViemRoundContract` plugs the existing `createRoundAgent` (salt and score persisted in `FileRoundStateStore`) into the chain.
- Web: service page shows a round timeline (phase, who committed, who revealed, median). Marketplace already rendered `median`.
- `scripts/demo/finalize-round.ts`; `e2e/one-round.e2e.test.ts`.

Contract state machine, commitment vector, wrong-salt / late-reveal / double-commit / early-finalise reverts and restart recovery were already on main (`RoundManager.test.ts`); I added the listing-opens-round-1 test.

## Spec deviations
- Added `GET /services/:id/rounds` (not in spec/03) so the page can list a service's rounds.
- `RoundView.committed` added to the frozen shape (needed for "who committed").
- "Bounty remains" is `bounty > 0`; the bounty is not yet debited per round (rewards arrive in 22).
- Local `K_MIN = 1` and demo windows live in `LOCAL_ROUND_CONFIG`, not `DEFAULT_ROUND_CONFIG`.
- Event ABI names the void flag `isVoid`; the schema field is `void` (existing mapping).
- Flaky, unrelated: `apps/critic` `probes.test.ts` budget test failed once under load, passed on re-run.
