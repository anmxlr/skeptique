# 07: Local stack harness and web shell (receipt)

## What changed
### Harness: `packages/harness` (`@skeptic/harness`), root devDependency
`startStack({ services })` returns `{ rpcUrl, chainId, contracts, apiUrl, services, stop }`. In order, it:
1. Loads the contracts package's Hardhat runtime in-process, resets the chain and compiles.
2. Serves Hardhat's JSON-RPC on a free port.
3. Calls `deployLocal(hre)`.
4. Starts the API against that chain on a free port.
5. Starts each named service starter `({ rpcUrl }) => { url, close }`.

`stop()` closes everything in reverse order. If boot fails midway, everything already started is torn down.

- Hardhat as a library doesn't register ts-node for a `.ts` config (its CLI does), so the harness registers it from the contracts package.
- Test `packages/harness/test/harness.e2e.test.ts` (`describe("harness boots")`):
  - boots the stack with an echo service and checks that `GET /health` reports chain 31337
  - after `stop()`, the RPC, API and service URLs all refuse connections
  - a second boot starts again at block 0

### Contracts
- `contracts/deploy/local.ts` exports `deployLocal(hre) → Record<name, address>`. It returns `{}` for now; **ticket 08 adds the first contracts here**. Exposed as `@skeptic/contracts/deploy`.

### API
- `buildApp(deps, fastifyOptions)` now takes `{ publicClient, contracts }` (dependency injection, so unit tests need no chain).
- `/health` returns `{ ok: true, chainId }`, or 503 `{ ok: false }` when the chain is unreachable.
- `src/index.ts` reads `HEDERA_RPC_URL` and `API_PORT`.

### Web shell
- Layout with skip link, brand, nav (Marketplace `/`, Critics, Sell, Buyer, Audit) using `aria-current`, and a theme toggle.
- Light and dark themes via CSS variables: they follow `prefers-color-scheme` by default, and the toggle saves the choice in `localStorage`.
- Responsive header: the nav wraps on mobile.
- Placeholder pages with headings.
- `lib/api.ts`: a typed client built on an `ApiRoutes` map (`/health` for now). Later tickets add routes typed from `@skeptic/shared`.
  - `apiClient()` needs `NEXT_PUBLIC_API_URL` and has no hard-coded fallback.
- `pnpm --filter web test` runs Vitest (pages + API client) and then Playwright (`playwright/nav-pages.spec.ts`, running against `next dev` on port 3107):
  - every nav page at 375px and 1280px: heading visible, all nav links visible, current link marked, no horizontal overflow
  - clicking a nav link changes page
  - the theme toggle works and survives a reload
- `apps/web/AGENTS.md` is generated by `next dev` (it re-creates the file if removed), so it's committed.

### CI
CI installs Chromium for Playwright and now runs `pnpm e2e`.

## Deviations / notes for the team
- **New package `@skeptic/harness`.** The harness needs the API and contracts packages as dependencies, so it lives in its own package instead of a loose root file. e2e tests in any package import `startStack` from it.
- **Demo services plug in through `ServiceStarter`.** Each service package (13) should export a starter function that the e2e tests pass to `startStack({ services })`.
- **Playwright needs Chromium.** Run `pnpm --filter web exec playwright install chromium` once per machine; CI does this itself.
- No spec/03 change. `/health`'s body isn't specified there; it now includes `chainId`.
