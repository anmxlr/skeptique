# 02: Spike: Hedera x402 and HCS (receipt)

## What changed
### Note: `spec/notes/hedera-x402.md`
Covers every item the ticket lists, each sourced to docs.hedera.com, the x402 repo (now `x402-foundation/x402`) or the npm registry:
- **Facilitator:** official `https://x402.org/facilitator` (fee payer `0.0.9185802`, no API key). Fallback: Blocky402 testnet `https://api.testnet.blocky402.com`.
- **Network and asset:** network id `hedera:testnet` (x402 **v2 only**). Asset is native **HBAR** (`asset: "0.0.0"`), with amounts in tinybars.
- **Packages:** `@x402/core`, `@x402/express`, `@x402/fetch` and `@x402/hedera`, all 2.30.0; plus `@hiero-ledger/sdk@2.90.1`. The v1 `x402-*` packages have no Hedera support.
- **Snippets and env vars:** a paywall snippet, a client snippet and an env-var mapping onto the existing `.env.example` names.
- **Settlement:** the settled tx id is read from the `PAYMENT-RESPONSE` header's `.transaction` field. HashScan pattern: `hashscan.io/testnet/transaction/<0.0.x@s.n>`.
- **EVM:** `https://testnet.hashio.io/api`, chain id 296. Inside Solidity, amounts are tinybars; JSON-RPC uses weibars (×10^10, and a nonzero value below 10^10 wei is rejected).
- **HCS:** topic create, message submit and mirror-node read-back, with the 1024-byte message limit.
- §10 covers the hollow-account finding, §11 has the live transcripts and §12 proposes spec/03 changes.

### Spike: `spikes/hedera-x402/`
Plain node with its own `package.json`, **outside the pnpm workspace**, run with `npm ci && ENV_FILE=<repo>/.env npm run spike`.
- `x402.mjs`: local Express paywall (`payTo` = SELLER). BUYER pays it through the facilitator, and the spike prints the tx id and HashScan link.
- `hcs.mjs`: creates the topic with a submit key if `HCS_TOPIC_ID` is empty, submits one message and polls the mirror node for it.
- `complete-hollow.mjs`: completes hollow accounts (see Deviations).

## Deviations / notes for the team
- **Hollow accounts (action taken on testnet):** SELLER, BUYER and the three CRITIC accounts were hollow (no key on chain), so the facilitator rejected the first payment with `invalid_exact_hedera_payload_signature_invalid`. `complete-hollow.mjs` completed all five, each by paying for a 1-tinybar transfer to DEPLOYER (Hedera's documented method). Any new payer account must be complete (note §10).
- **"Ax402"**, named in prd §4.1, is not on Hedera's facilitator page. That page lists Official x402, Launa and Blocky402.
- **Field name mismatch:** the docs and spec call the settle-response field `transactionId`, but the shipped code returns `transaction`. Read `transaction`.
- **The tx id's account is the facilitator** (`0.0.9185802@…`), not the buyer. It is not a hex hash, so never store it as `bytes32`.
- **SDK package:** Hedera docs now say to use `@hiero-ledger/sdk`, not `@hashgraph/sdk`. In the x402 path, import SDK classes from `@x402/hedera` to avoid loading two copies of the SDK.
- **HashScan topic URL** (`/testnet/topic/<id>`) is printed by the spike but is not documented by Hedera.
- **spec/03 is unchanged.** Note §12 proposes five one-line clarifications (tinybar units for `maxPrice`/`pricePerCall`/stake; signer shape; `txId` format; HCS ≤1024 B).
- **Testnet spend:** 2 settled payments of 0.001 HBAR each (the first attempt failed before settling), plus HCS and completion fees, all well under 1 HBAR.
