## What changed
- **`spec/notes/ens.md`**
  - Phase A (commit `c8154fa`): research sourced only from ENS docs, ENSIPs and `ensdomains` repos.
  - Phase B (commit `dcfa607`): adds a "Phase B result" section with the live addresses, the read-back and the negative checks. It resolves most "Unverified" items (gas, child expiry, `initialize` grants, `getEnsText` on a v2 resolver, factory address prediction). Each fix is marked "Phase B correction" and cites the source line.
- **`spikes/ens-sepolia/ens.mjs`** (new): a plain-node viem script outside the pnpm workspace, the same pattern as `spikes/hedera-x402`. It runs the note's "Phase B plan" end to end:
  1. Registers `skeptique.eth` by commit-reveal, paying with free MockUSDC.
  2. Deploys `UserRegistry` proxies for `skeptique.eth`, `svc.skeptique.eth` and `critic.skeptique.eth`, and links them with `setSubregistry` and `setParent`.
  3. Deploys one `PermissionedResolver` for `spike.svc.skeptique.eth`. The operator holds only `ROLE_SET_TEXT_ADMIN`. One `multicall` of `grantSetterRoles` gives the relayer the 4 `eth.skeptique.*` score keys and the seller `url` and `description`.
  4. Registers `spike.svc.skeptique.eth` to the seller with `roleBitmap 0`.
  5. The relayer writes `eth.skeptique.score`; the script reads it back with `getEnsText`.
  6. Simulates six permission checks.

  Every step checks chain state first, so a re-run sends nothing (run 3 in the transcript).
- **`spikes/ens-sepolia/transcript.txt`** (new): all three runs, with tx hashes and gas. It holds addresses and hashes only, no secrets.
- **`spikes/ens-sepolia/package.json`** and **`package-lock.json`** (new): `viem ^2.57.16`, `dotenv`.
- **`.env.example`**: `ENS_OPERATOR_PRIVATE_KEY` (phase A, commit `2ceea05`).

## Spec deviations
- **Record keys:** the spike writes `eth.skeptique.score`, the note's recommended ENSIP-5 form, not spec/03's `skeptique.score`. The prefix is derived from `ENS_PARENT_NAME`.
- **Not applied, for a human decision:** the note proposes three spec/03 changes; `spec/03-interfaces.md` is untouched.
  1. Required: one PermissionedResolver per service subname. The seller's subname has `roleBitmap 0`, so it can't change its resolver or be transferred. In that resolver the relayer holds the score keys and the seller holds `url` and `description`. All critic subnames share one relayer-only resolver.
  2. Recommended: the `eth.skeptique.*` key prefix.
  3. Optional: seller-written ENSIP-26 `agent-endpoint[web]` / `agent-context`.
- **Note corrections** (applied to `spec/notes/ens.md`):
  - The Sepolia relayer key is `SEPOLIA_RELAYER_PRIVATE_KEY`, not `RELAYER_PRIVATE_KEY`.
  - Seller `safeTransferFrom` reverts with `TransferUnsafeUntilRegistryIsEmancipated` rather than `TransferDisallowed`. `unsafeTransfer` gives `TransferDisallowed`.
- **Spike values:** the slug `spike` and score `87` are CLI defaults in the spike script, not product code.
- **Run 1** stopped at step 3. A load-balanced RPC returned the parent's expiry as `0` right after `register`. The fix pins reads to the latest receipt block (commit `2bcdace`). The note records this as a gotcha for ticket code.
- **Critic resolver:** the plan's `critic` registry exists, but no critic subname or shared critic resolver was created. That was outside the plan's steps.
