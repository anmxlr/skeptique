# 19: Marketplace confidence-adjusted ranking

## What changed

The existing pure shared ranking formula remains unchanged. A real-chain source now supplies the latest successful finalized median, reveal count, successful-round count and canonical block timestamp to it. Void finalizations do not overwrite a successful review. The marketplace shows adjusted rank, a labeled confidence meter, probation, and links to service details. The local harness composes this source with verified ServiceRegistry listings and the real RoundManager from ticket 17; no mock finalization data enters the product path.

Wrote and committed the named failing acceptance first: before the dependency merge the harness had no deployed RoundManager. A subsequent fixture failure exposed that registry listings correctly omit unreachable suites; the acceptance now starts actual demo HTTP services instead of fake endpoints.

- `pnpm --filter shared test -t rank`: **15 shared tests pass**, including all three ranking tests. Installed pnpm runs the full package suite for this syntax. Explicit `vitest run -t rank`: **3 ranking tests pass**. These cover count-sensitive ordering, age decay/floor and stable ties.
- `pnpm e2e -t 'marketplace ranks services'`: **1 named test passes**. Lists three real services, registers five actual local critics and finalizes two score-80 rounds with three versus five reveals; API orders them 2,1,3, and SSR shows the confidence meter, detail link and probation.
- API: **41 tests pass**, including three event-source regressions for latest valid history, shared-block RPC deduplication and refresh after a new finalization.
- Critic: **47 tests pass**. Web: **25 unit tests and 12 browser tests pass**. Browser checks cover shell/navigation at 375/1280px; the actual ranking content is checked by the named chain/API/SSR acceptance and focused component tests.
- API, harness and web TypeScript checks pass; scoped Biome check passes.

## Research, efficiency and boundaries

See `docs/research/19-ranking.md`: reviewed upstream viem event-read documentation and Miller's analysis of rating uncertainty. Preserved the frozen formula; the displayed confidence is a count/age heuristic, not a statistical confidence interval. One finalization-log scan serves every listed service, and finalization timestamps share one RPC lookup per distinct block hash. Tests assert those counts. No stale cross-request ranking cache was introduced.

History is rebuilt per request and scanned from genesis: suitable for the hackathon, not a production indexer. API production deployment wiring belongs to ticket 21. ENS published snapshots belong to ticket 20 and are distinct from this time-decayed ranking input. Shared spec schemas and formulas were not changed.
