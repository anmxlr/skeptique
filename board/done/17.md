# 17: Real collateral settlement and visible consensus verdicts

## What changed

- The existing stake-weighted median and config-driven personas are retained. Settlement reads aligned scores directly, removing the repeated score search, and uses an overflow-safe median threshold with ties going low.
- RoundManager locks real CriticRegistry collateral at commit. A critic cannot withdraw or reuse that collateral in a concurrent round. Valid settlement releases all participating locks and debits outlier stake exactly once. The corresponding native funds stay in a per-round `slashedFunds` pool reserved for ticket 22; no payout or seller withdrawal path is introduced.
- The local harness now deploys and authorizes the actual RoundManager. `/rounds/:id` uses pinned chain reads and decoded events. `/critics` shows the latest valid finalized review's actual honest/slashed/outlier status and amount. The new Round page displays honest/outlier flags; an outlier is not falsely called slashed when the configured penalty rounds to zero. Frozen shared schemas remain unchanged.
- Public GET responses allow cross-origin browser reads without credentials. Write routes retain their existing policies. Regression coverage verifies this does not grant POST access.
- Critic verdict indexing processes the reveal history once instead of filtering and sorting it for every critic. Void event handling is ready for ticket 25 without publishing a false median or punishment verdict.

## Research and implementation choices

- [Yin et al., Byzantine-Robust Distributed Learning](https://arxiv.org/abs/1803.01498) analyzes median and trimmed-mean aggregation for distributed learning. It motivates adversarial aggregation tests, but its statistical guarantees are **not** claimed for this stake-weighted review market. A colluding stake majority and shared wrong beliefs remain outside the protocol's defenses, as specified.
- [OpenZeppelin ReentrancyGuard source](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/utils/ReentrancyGuard.sol) and [Reentrancy After Istanbul](https://blog.openzeppelin.com/reentrancy-after-istanbul) inform collateral handling. Existing withdrawal clears accounting before the external transfer; settlement adds no external recipient payment. No guard dependency is added without a demonstrated need, and no transient-storage support is assumed on Hedera.
- Existing [fast-check](https://github.com/dubzzz/fast-check) supplies reproducible property tests; the real local chain and existing harness replace a mock deployment. No new runtime dependency or MATLAB benchmark is needed for this deterministic contract path.

## Limits and handoff

- Ticket 22 must consume the reserved slash pool and implement honest-critic claims; retained funds are not paid out here.
- Ticket 25 must implement too-few-reveal void settlement and non-revealer penalties, releasing **every committer's** collateral. Until then a failed round remains locked; the valid-round path is complete and tested.
- Critic concurrency is deliberately limited to one active round per stake so the same funds cannot back multiple simultaneous liabilities. Full-history event scans remain suitable for the hackathon; a persistent incremental index belongs in a later scalability change.
- Listing-driven round admission, testnet deployment and sponsor acceptance remain their owning tickets. No live sponsor transaction is claimed here.
