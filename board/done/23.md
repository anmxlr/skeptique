# 23: HCS audit log of rounds and slashes

## What changed

- `packages/shared/src/hcs.ts` (`@skeptique/shared/hcs`): zod schemas for the three audit messages (`round_finalized`, `critic_slashed`, `agent_spend`), `encodeAuditMessage` (validates, enforces the 1024-byte HCS limit), `auditKey` (event identity used for dedupe) and `readAuditLog` (reads the topic from the mirror node, newest first, skips rows that are not valid audit messages).
- `apps/relayer/src/hcs.ts`: `createAuditLog(publisher)`, the shared poster. Ticket 26 can post `agent_spend` with it. Replays never post twice: the topic is the checkpoint (existing keys are read back from the mirror node on first use) plus serialised in-memory dedupe.
- `apps/relayer/src/hcs-hedera.ts`: Hedera SDK publisher (`TopicCreateTransaction` with a submit key when no `HCS_TOPIC_ID`, `TopicMessageSubmitTransaction`), only calls from spec/notes/hedera-x402.md §8.
- `apps/relayer/src/hcs-source.ts`: one bounded catch-up pass over `RoundFinalized` and `CriticSlashed` logs, posting each through the audit log. It is not yet wired into `cli.ts`.
- `apps/web/components/audit-log.tsx`, Audit page: reads the mirror node directly in the browser (not the API); newest first; links to the mirror REST row per message, the HashScan topic and, for `agent_spend`, the HashScan transaction.
- `.env.example`: `NEXT_PUBLIC_HEDERA_MIRROR_NODE_URL` and `NEXT_PUBLIC_HCS_TOPIC_ID` for the browser.
- Dependency: `@hiero-ledger/sdk@^2.90.1` added to the relayer.

## Spec deviations and notes

- spec/03 only says `{type, ...fields, ts}`. Field names are my choice, frozen in `AuditMessageSchema`; ticket 26 should use `agent_spend {payer, merchant, amount (tinybars), txId, ts}`.
- The HashScan topic URL pattern is undocumented (note §8); the Audit page uses `hashscan.io/testnet/topic/<id>` anyway, alongside the documented mirror REST link.
- `ts` is wall-clock at posting time; the authoritative time is the mirror `consensus_timestamp`.
- The live test posted one message to the real audit topic.
- Not done: the relayer CLI loop does not yet call `relayAuditFromChain`; no live check of the Audit page in a browser.
